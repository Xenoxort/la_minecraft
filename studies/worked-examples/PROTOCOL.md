# Worked examples for new Hell’s Kitchen recipes

Does seeing previous discovery steps help GPT-6 Luna solve harder recipes? Does an example made by GPT-6.2 Astra help more than an example made by Luna?

## Minecraft task and calibration

A cook has four hidden recipes. Each requires one ranked ingredient from each of four shelves and an order ticket. The public clue gives the sum of the four ranks. A test returns the exact number of correct shelf choices. Minecraft’s own recipe engine rejects wrong sets and produces food for a correct set. The bot deposits every result in the delivery chest. The server verifies the chest independently at the end. The bot starts stocked at the table.

Four separate calibration kitchens test four, five, and six choices per shelf, using independent Luna and the same action and token budget planned for the students. Among widths with a mean between 1 and 3.5 verified orders, choose the closest to 2.5 and prefer the larger width if tied. If none qualify, apply the same distance and tie rule to all widths. The fixed goal is to leave room to improve at the six-minute cutoff. Calibration and physical smoke tests are excluded from the student outcomes.

## Donor examples and matched student conditions

Eight donor kitchens each run once with Luna and once with Astra. Both donor models start from scratch with the same clues, tool access, 30 decisions, and per-decision token ceiling. Recording 30 decisions per donor provides enough opportunity for the two models to produce successful paths on the same tasks.

Build two packs of four worked examples. In ascending donor-seed order, take the first recipe both models actually delivered with at least three attempts. Use at most one recipe per donor kitchen. For both sides, show the first two unsuccessful tests and the actual third test, with the same rank-sum clue and the same template. Each row shows the feedback and surviving candidate count. The split column shows how many candidates each possible feedback score would leave before the test. These numbers are derived deterministically from the visible clue and prior tests. Example selection and annotation use the same procedure for both donors. The packs have exactly the same text length and number of rows. They use ranks only. The donor and student recipes have distinct verified ingredient combinations.

Twelve new kitchens each run all three student conditions with the same GPT-6 Luna configuration:

| Condition | Material |
| --- | --- |
| From scratch | Clues, feedback, and the student’s own observed tests |
| Luna examples | Same inputs and four examples from earlier Luna runs |
| Astra examples | Same inputs and four examples from earlier Astra runs |

Each of the six possible arm orders occurs twice. Every student has a six-minute deadline and twenty 18-second decision slots. Each decision has at most 3,200 input and output tokens combined, including examples. A teacher’s identity is omitted from the student prompt. Each student receives one pack at the beginning and can consult it throughout the run.

## Outcomes

The primary outcome is the number of orders delivered by six minutes. Report all three paired contrasts over twelve matched kitchens with descriptive matched bootstrap intervals. The most relevant cost comparison is Astra examples against Luna examples. Student versus independent discovery measures the benefit of access to the supplied experience.

Secondary outcomes include attempted crafts, attempts per order delivered, time to first correct craft, time through whole-menu completion or cutoff, and token usage. Use the cutoff for an event that never occurs and show the number observed. Track API and invalid-action errors, duplicated guesses, provider request times, and timestamps of real crafting actions. Count input and output tokens for each donor cohort alongside student tokens. This includes the cost of eight donor runs per model even though the final example packs draw on four kitchens.

An effect of practical interest is about half an extra recipe on average, or fewer attempts with similar delivery. The study estimates the effect of short matched worked examples generated by this extraction procedure. Both donors show actual search decisions on the same solved tasks. The design measures the quality of their examples in that shared subset, and donor completion and token reports retain the results on all eight donor kitchens.
